# Security requirements (SEC-xx) that have code in the repository.
# scripts/check-sec-coverage.sh fails unless every ID listed here has a test
# named after it, and unless every SEC ID mentioned in non-test code is listed.
#
# Add an ID when you write the first code for it. One ID per line; text after
# the ID is a reminder of what it covers.

SEC-01  Setup token generated on first start, required by setup, deleted afterwards
SEC-02  First admin: password rules, forced TOTP enrollment, 10 recovery codes
SEC-03  Argon2id password hashing
SEC-04  2FA (TOTP or passkey) mandatory for every user
SEC-05  Login rate limiting: exponential backoff, 15-minute lock after 10 failures, failures logged
SEC-06  Session tokens: random, hashed, idle and absolute timeouts, list and revoke
SEC-07  Step-up re-authentication for sensitive actions
SEC-08  sentinel-server reset-admin, only as root or the data directory owner
SEC-10  TLS by default (self-signed, ACME); plain HTTP only on loopback or behind a TLS proxy
SEC-11  Content-Security-Policy, X-Frame-Options, Referrer-Policy
SEC-12  CSRF protection: SameSite=Strict cookies plus Origin check
SEC-13  WebSocket upgrades check the Origin header
SEC-14  public_url, base_path and trusted_proxies; X-Forwarded-* only from trusted proxies
SEC-40  Append-only, hash-chained audit log
SEC-41  Audit log view, CSV/JSON export, and verify command
SEC-15  Server-side input validation, parameterized SQL, no shell string building
SEC-42  Stored secrets encrypted with AES-256-GCM using <data dir>/secret.key
